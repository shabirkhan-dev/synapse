## What

The first CI run of the `e2e` job (commit 49f4c48) failed two tests that passed locally: two tabs
reloading at once, and forgot password. The report upload found no files.

## Why / Context

Run 43144240217. Reproduced locally with `--repeat-each=5 --workers=4`.

## Resolution

Done in commits `fix(auth): answer a just-replaced refresh token with an access token`, `fix(console): keep submit buttons disabled until the page hydrates` and `test(e2e): fix test races and ci diagnostics`.

- **Real bug — refresh reuse under load:** the console's Web Lock does not stop two tabs from sending the same refresh cookie every time; reuse detection revoked the session (confirmed in `auth_sessions`). Fix (ADR-0007 amendment): within `AUTH_REFRESH_REUSE_GRACE_SECONDS` (10 s) of the rotation, the just-replaced token gets an access token only (no new refresh token, no `Set-Cookie`); the compare-and-swap loser of two simultaneous refreshes is treated the same; later reuse still revokes. Migration `0013_refresh_token_rotated_at`.
- **Real bug — dead clicks before hydration:** a submit before React attached the handler did nothing. `SubmitButton` is disabled in the server HTML and until hydration, in every form.
- **Test races:** filling "Email" right after clicking a link to another auth page could hit the old page's field (wait for the new heading, exact match — the route announcer repeats titles); API-side sign-ups now send their own `x-forwarded-for` (`TRUST_PROXY=true` in the e2e API) so suite size never reaches the 10-per-IP sign-up limit.
- **CI:** report upload sets `include-hidden-files` (`.output` is a dot folder); the job prints the API log tail on failure.
- **Validation:** 3 consecutive stress runs × 25 tests (5 repeats, 4 workers, no retries) all pass; 0 of 10 two-tab sessions revoked (was 1). API: grace answer, revocation after the window, two simultaneous refreshes both succeed with one rotation, cookie untouched in the grace answer, rotation time stored in Postgres, config default/0/limit. Console: `SubmitButton` disabled in server HTML, enabled in the browser.
