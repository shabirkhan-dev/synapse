## What

Compose runs the stack for development; nothing describes a production deployment.

## Why / Context

Roadmap Phase 3 `deploy/`. ADR-0007 needs console and API on one site behind TLS; migrations run
from the API image; backups and health are undocumented.

## Proposal or Ask

`deploy/`: production compose (Caddy for TLS and one site: `console.<domain>`, `api.<domain>`),
API image runs migrations on start, worker, Postgres with scheduled `pg_dump` backups and a restore
runbook, health checks wired to the readiness endpoint, logs/traces to Langfuse.

## Scope

**In scope:**

- compose file, proxy config, backup job, runbooks (deploy, restore, rotate secrets)

**Out of scope:**

- Kubernetes, cloud-specific infrastructure

## Validation

- the stack boots from the compose file with production settings; a backup restores into a fresh database

## Resolution

Landed (`feat(deploy): …`, `fix(docker): …`):

- `deploy/compose.yml`: Caddy 2.10 (automatic HTTPS, HTTP→HTTPS, HSTS, no response compression on
  the API so streams are not buffered), api (migrations on start, `TRUST_PROXY`, CORS and `APP_URL`
  for `https://${CONSOLE_HOST}`), worker, console (`NEXT_PUBLIC_API_URL` build arg), Postgres
  (no published port), `backup` (daily `pg_dump -Fc`, kept 14 days). Only Caddy publishes ports;
  logs rotate 10 MB × 5. `deploy/.env.example`, `deploy/README.md`.
- `deploy/backup/restore.sh`: restores into an **empty** database only (`--replace` drops and
  recreates; refuses while connected). Restoring with `--clean` over a live database fails on
  pg-boss's partitioned tables — found in the rehearsal.
- Dockerfile bug fixed: the build stage copied only the root `node_modules`, but Bun links
  workspace dependencies per package, so the api/worker bundles could not resolve `drizzle-orm`,
  `postgres`, `@opentelemetry/*`. Images had never been built before. Removed redundant
  `apk add wget`; optional `build_ca` secret for TLS-inspecting proxies.
- Runbooks Live: deployment, database-backup, database-recovery, monitoring, new rotate-secrets.

Validation (local, `console.localhost` / `api.localhost`, Caddy internal CA): images build (api
182 MB, worker 178 MB, console 338 MB); all six services up, api/console/postgres healthy;
readiness 200 with database ok; sign-up 201 with `access-control-allow-origin:
https://console.localhost` and a `Secure; HttpOnly; SameSite=Strict` refresh cookie; console pages
200 over HTTP/2; migrations applied on first start, no-op on restart; worker ran a re-embed job; a
backup restored into a fresh database with identical row counts, 15 migration entries, an identical
vector (distance 0) and the HNSW index; `--replace` live restore and the stack recovered healthy.

Not verified: Let's Encrypt issuance (needs public DNS), real email and model calls (dummy keys).
CD (`cd.yml`) still has placeholder steps — syn-052.
