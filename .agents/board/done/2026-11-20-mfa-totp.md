## What

Users can turn on TOTP; sign-in then asks for a 6-digit code, with one-time recovery codes.

## Why / Context

Gap review 2026-11-19 (item 5): no MFA.

## Proposal or Ask

RFC 6238 in `@synapse/security` (no new SDK), secret encrypted at rest, rate-limited code checks, recovery codes hashed. Done with unit vectors from the RFC, API tests and an e2e that enrols and signs in.

## Scope

**In scope:** packages/security, packages/database, apps/api auth, apps/console auth/account, tests/e2e.

## Validation

- lint, typecheck, unit and integration tests, e2e where a flow changes

## Resolution

`@synapse/security`: TOTP (RFC 6238, verified against the RFC's SHA-1 vectors), base32, recovery
codes, AES-256-GCM secret box, MFA challenge signer (separate derived key). Migration 0022 (users'
mfa columns, `mfa_recovery_codes`). API: `MfaService` + `DrizzleMfaRepository`; `/auth/mfa` status,
setup, enable (ten recovery codes once), disable; sign-in returns `{ mfaRequired, challenge }` when
on, `POST /auth/sign-in/mfa` finishes it; codes work once (stored counter), recovery codes are spent,
5 tries per 5 min per user; API keys cannot reach `/auth/mfa`. New env `AUTH_ENCRYPTION_KEY`
(`.env.example`, deploy env and compose, Doppler dev). Console: code step on sign-in (with recovery
code and start over), Account card with QR (`qrcode` 1.5.4), key, confirm, recovery codes, turn off.

Validation: security 23 pass (RFC vectors, window, replay, sealing, challenge never an access token);
API 4 tests (setup sealed, challenge then code once, forged challenge, recovery once, off, rate limit,
API keys refused) + Postgres repository test; console 3 tests; e2e (turn on from Account with a
computed TOTP, sign out, sign in with the next code).
