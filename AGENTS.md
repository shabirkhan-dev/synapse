# Agent instructions (Synapse)

Universal instructions for AI agents (Cursor, Copilot, Claude Code, Windsurf, Cline, Aider, etc.).
Read this file first when working in this repo.

## Project overview

Synapse is an AI platform monorepo managed with **Turborepo + Bun**. Apps, shared packages, and
scripts, all wired into a single lint/format/build/test surface.

## Before you write code

Agent guidance lives in [.agents/](.agents/README.md) — the same files for every tool (Claude Code
via `CLAUDE.md`, OpenCode via `opencode.json`, skills via `.agents/skills`; see
[docs/agents/tool-compatibility.md](docs/agents/tool-compatibility.md)). Load these in order:

1. This file
2. [.agents/README.md](.agents/README.md) — what is in `.agents/` and the coordination protocol
3. [.agents/rules/](.agents/rules/) — binding rules: architecture, backend architecture, frontend
   architecture, configuration, coding standards, TypeScript, Bun, Rust, database, API design,
   security, testing, error handling, documentation, progress tracking
4. [.agents/memory/](.agents/memory/) — current architecture, decisions, conventions, known constraints
5. [.agents/plans/roadmap.md](.agents/plans/roadmap.md) — where the project is, what is next
6. The matching playbook in [.agents/skills/](.agents/skills/) (`<task>/SKILL.md`)

**Track every task on the board** (`.agents/board/`: claim `open/ → doing/`, close to `done/` with
the commit), keep the roadmap current, and **end every reply with a Roadmap block** (Where we are /
Next / Left). See [.agents/rules/progress-tracking.md](.agents/rules/progress-tracking.md).

The four architecture rules that matter most: one owner per capability; domain packages never
import vendor SDKs (only `database`, `adapters` and `providers` do); every long job saves its state and can
resume; every answer records the model, prompt version and embedding version.

App layering: backend modules flow route → controller → service → repository (services never build
HTTP responses, only repositories touch the database); console features flow page → container →
query/mutation hook → plain service → central API client. Env is read only in each app's
`config/`. Modules and features import each other only through `index.ts`. These are enforced by
`bun run architecture:check`.

For coordinated multi-agent work, also load
[.agents/agent-contract.md](.agents/agent-contract.md), exactly one charter from
[.agents/roles/](.agents/roles/README.md), [.agents/worktrees.md](.agents/worktrees.md) and your card
from [.agents/board/](.agents/board/README.md). The short version: claim a card before coding, work in your own worktree on
`agent/<role>/<card-slug>`, write only inside the card's scope, stage explicit paths rather than
`git add -A`, and record real validation output on the card. `main` is integration-only.
[.agents/ownership.yaml](.agents/ownership.yaml) is the machine-readable role-to-path map.

## UI design context

Shared UI lives in `packages/ui` (`@synapse/ui`): shadcn/ui on Base UI (style `base-mira`), HugeIcons, Tailwind v4. Add primitives
with the shadcn CLI from `packages/ui` (`bunx --bun shadcn@latest add <name>`) rather than writing
them by hand. Icons are HugeIcons only; do not add lucide. The console's UI is being built from
zero, so there is no existing design to infer from yet.

## Documentation

Project docs live in [docs/](docs/README.md): architecture, packages, decisions (ADRs),
development, agents, API, runbooks and guides. Each page has a Status line (`Live`, `Planned`, or
`Placeholder`). The API reference is generated by `apps/api` (`/api/docs`, `/api/openapi.json`).
Update docs in the same change as the code (`.agents/rules/documentation.md`).

## Conventions

### Code style

- **Formatter**: oxfmt. Tabs, line width 100. Applies to `apps/**/*.ts(x)`, `packages/**/*.ts(x)`,
  root config files. Run `bun run format` or rely on pre-commit hook.
- **No ESLint/Prettier**: oxlint and oxfmt are the only lint/format tools for TS/JS in this project.
- **Naming**: PascalCase for components; files match component name. Hooks use `use*` prefix;
  utility functions are plain named exports.
- **Imports**: Prefer workspace imports as `@synapse/<package>` (e.g. `@synapse/ui`).
  Group: external → workspace → relative. No unused imports.
- **Types**: Explicit types for props and public APIs. Avoid `any`; use `unknown` and narrow.
- **Errors**: Handle explicitly — log and rethrow, or use result types. No silent catches.
- **Size**: Small, single-responsibility functions and components. Extract when complexity grows.

### Project structure

- **Monorepo**: Apps in `apps/`, shared code in `packages/`. When a change applies across apps,
  prefer changing a shared package.
- **New apps**: Add under `apps/`, wire into `turbo.json` tasks if needed.
- **New packages**: Add under `packages/`, export via `@synapse/<name>`.
- **Shared UI**: components live in `packages/ui` (`@synapse/ui`), added with the shadcn CLI.
  Tailwind tokens live in `packages/ui/src/styles/globals.css`. Icons are HugeIcons only; do not
  add lucide.
- **TypeScript config**: Extend from `packages/typescript-config/base.json` (or `nextjs.json`
  for Next.js apps).

### Git and commits

- **Pre-commit hooks** (Lefthook): auto-format, lint, typecheck, large-file guard (2 MB max),
  secret scan, architecture check. Hooks run automatically if installed via `bun run prepare`.
- **Commit messages**: Enforced by `commit-msg` hook — Conventional Commits only
  (`feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert`), **all lowercase**,
  10–200 chars, no WIP. Example: `feat(rag): add hybrid search endpoint`.
- **Do not commit**: build output (`.next/`, `dist/`, `target/`), `node_modules/`, `.env` files,
  cache dirs. These are in `.gitignore`.
- **Separate concerns**: Don't mix lint/format-only fixes with feature changes in the same commit.

### Per-language notes

| Language | Lint | Format | Test |
|----------|------|--------|------|
| **TypeScript/JS** | oxlint | oxfmt | Vitest/Jest (if added) |
| **Rust** | Clippy | rustfmt | `cargo test` |
| **Bash** | ShellCheck | shfmt | — |

### Docker

Postgres (pgvector), the API, and the Next.js console via Compose fragments under `docker/compose/`
(merged by root `docker-compose.yml`, Compose v2.20+, no `version:` key):

```bash
cp .env.example .env
docker compose up -d --build
```

Defaults: console `:3000`, API `:8000`, Postgres host `:5433`. Host-only API/console: start
`postgres` only, then `bun run dev`. See `docker/README.md`.

## Before finishing any task

1. Move your board card to `done/` with the commit, and update `.agents/plans/roadmap.md`.
2. Run `bun run lint` from repo root — fix any errors.
3. Run `bun run format` from repo root — ensure formatting is clean.
4. If you changed TypeScript, run `bun run typecheck`.
5. Do not leave dead code, unused imports, or `any` types.

# This is NOT the Turborepo you know

Turborepo configuration, task behavior, and CLI commands can vary between installed versions and may differ from your training data. Resolve the `turbo` package from this file's directory or relevant workspace; in monorepos, it may not be visible from the repository root. For example, run `node -p "require.resolve('turbo/package.json')"` from a workspace that depends on `turbo`.

Read `docs/README.md` inside that installed package first, then read the relevant pages from its `docs/` directory before changing Turborepo configuration or commands. Heed deprecation notices. These bundled docs match the installed package version and are available without network access.

This block is written and re-added by `turbo` before repository-scoped commands when an AI agent is detected. In the Turborepo source repository, its template is defined in `crates/turborepo-cli/src/cli/agent_guidance.rs`. Removing the managed block while updates are enabled means a later qualifying invocation will add it again. Set `"agentGuidance": false` in the root `turbo.json` or `turbo.jsonc` to opt out; this does not remove an existing block. Keep the block committed with your work to avoid an uncommitted change on the next agent invocation.
